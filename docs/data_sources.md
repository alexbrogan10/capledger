# Data Sources

## Demo dataset (current state of this repository)

**DEMO DATA — NOT OFFICIAL NFL DATA.**

Cap Ledger currently ships with a single data source: a synthetic demo dataset
generated by `backend/app/seed/`.

| Field | Source | Real or synthetic |
|---|---|---|
| Team names, abbreviations, conference/division | `app/seed/teams_data.py` | Real (public franchise facts) |
| Player names | `app/seed/demo_data.py` name-pool generator | **Synthetic** — not real players |
| Player ages/experience | Randomly generated within realistic bounds | Synthetic |
| Contract dollar figures (AAV, guarantees, signing bonus, cap hits) | Randomly generated within position-realistic ranges, then scaled per team to a plausible cap-utilization ratio | Synthetic |
| League salary-cap figures | A synthetic baseline + assumed 6%/year growth rate | Synthetic — **not** the real reported NFL cap |

Collection date: N/A (generated, not collected). License: N/A (no external
dataset is used). Generation is fully reproducible: `app/seed/demo_data.py`
seeds Python's PRNG deterministically per team (`random.Random(f"capledger-demo-{team}-{n}")`),
so re-running `python -m app.seed.seed` against a fresh database produces the
same dataset.

### Transformations applied

1. Roster generation from a fixed position-count template (53 players/team).
2. Contract structuring: AAV → total value → signing bonus (≈70% of the
   guaranteed amount) → base-salary schedule (linearly escalating) → per-year
   proration via the cap engine's proration rule.
2. A uniform per-team scaling pass so a team's current-season commitments land
   at a realistic (and cap-compliant, with some variance) fraction of the
   assumed league cap — see `generate_team_roster()` in `demo_data.py`.
3. A small number of already-released players per team, with realized dead
   cap in the current season, so dead-cap figures aren't uniformly zero.

### Known limitations of the demo dataset

- Because only currently-modeled contracts are included, **future-season team
  commitments trend down** as contracts expire — real teams continuously
  re-sign players, so this understates real future commitments. This is a
  known artifact of a single-snapshot synthetic dataset, not a claim about how
  real cap trajectories behave.
- Positional AAV ranges are approximate and not calibrated to any specific
  real season's market.

## Replacing the demo dataset

The seed pipeline is intentionally decoupled from the API and cap engine: any
future data source needs only to populate the same six tables (`teams`,
`players`, `contracts`, `contract_years`, `team_cap`, `team_rosters`) via the
same SQLAlchemy models. `backend/app/seed/seed.py` is the reference loader to
follow for a real pipeline (raw → cleaned → validated → loaded).

Cap Ledger does not scrape or redistribute any real, licensed, or proprietary
NFL/NFLPA contract data. A production deployment would need to source
contract data appropriately (e.g., licensed data provider or manually curated
public reporting) and comply with that source's terms.
